## 1. Phase inventory

- **M0 retire-wait + resets (KRN:846-897).** All CTAs. `tid<8` polls `retired[p] >= epoch-1` (slot 31, system scope), grid barrier, then grid-strided zero of `a2_done`/`part_done` (slots 29/30) and `mps_state` words+timestamps (slot 60). Exp_56 fix: zeroes the **next** epoch's `dest_counter` parity half (`(epoch+1)&1`, KRN:880-894, pperr 262144 if self cell nonzero). Publishes nothing. Timing: small; it is the cross-epoch serialization point.
- **M0.5 decision pre-pass** — M19 arm KRN:911-947 (histogram `my_ids` into `hcnt`, two grid barriers, derive 256-bit `s_dec`); M20 arm KRN:899-910 (load precomputed slot-65 bitmap, zero barriers — the +1.2 ms deletion). Default build: absent.
- **M1 dispatch (KRN:949-1157).** All CTAs, one warp per token (`gw`, KRN:968-970). Inputs: `my_ids`/`my_wgt`/`hidden` (slots 0/1/2). Outputs: LL128 rows into peers' `a_ll` (slot 3), `pull_stage` (12), `pull_cnt` (13), `pushed_count` (6). Publishes (last CTA's tid0, KRN:1103-1155): `release_signal_batch_system` then per-peer `rows_done[cur]` epoch|count (slot 5) and 8 `chunk_ready[cur][c]` epoch|fill words (slot 50) — M19 decision words are stored **before** the release so they are ordered-before the epoch word (KRN:1107-1128). ~557 us class.
- **M2 receive/unpack (KRN:1159-1345).** All CTAs. tid0 spins on all 8 `rows_done` (KRN:1185-1201, pperr 16777216); warp-strided bounded polls of the 64 `chunk_ready` words (KRN:1205-1218, pperr 8388608); grid barrier; fills cached to `s_fill`/`s_ns`; per-warp `k0p6_unpack_row_nopoll` of `a_ll` row r into `a_dst` (8), `sc_stage` (9), `recv_eid` (10), `recv_wgt` (11) (KRN:1266-1306); per-slot shared histogram `s_cnt` -> `hcnt` (24) at KRN:1343; writes `row_remaining` (26) at KRN:1303 (write-only in m15 — see risks). Hole-sentinel clamp fix KRN:1314-1340.
- **M3-M5 plan+scatter (KRN:1347-1467).** Barrier M3 (1369). bid0: count-reduce/scan/cursors + `tile_desc` build — `(b0<<4)|gcount` G-stack packing, slots 53/54 (KRN:1372-1397, overflow pperr 4194304). bid1: CSR scan `pull_cnt`->`pull_ptr` (1398-1402). bid>=2: `part` zero / scale transpose (dead-ish in mode 12, 1403-1431). Barrier M4 (1433); `pad` + scatter (donor or M17/M18/M19 variant, KRN:1436-1453) filling `sti` (14, packed `row|s<<24`) and `swt` (15, the **topk weight**), `pull_src_fill` (19) at 1454; barrier M5 (1456).
- **M6 GEMM1 (KRN:1470-1486).** **All 256 CTAs**, donor stride (P1 defaults `blockIdx.x`/`kCTAs`, P1:249-254 — never overridden). Inputs `a_dst`, `sc_stage`, `W13`/`S13` (35/36), `sti`/`sei`/`nvi`; outputs `A2q` (27) + `DQ2` (28); per-32-block `a2_done` arrival via `N2GM_TASK_DONE_HOOK` (KRN:314-319, 383).
- **M7 slab loop (KRN:1498-1718).** Two slabs (S=2, KRN:281-283). Compute CTAs (`!is_service_cta`) run `n2p6m15_phase2_body` over task range `[slab*8*ntiles, +8*ntiles)` with NC-major decode (KRN:413-416), dense compute-id start/stride `nct-C` (KRN:336-346, 409-410). a2 wait per sub-block (`poll_local_count<8>`, KRN:321-334). Epilogue = remote accumulate into owners' `slots` (61). Per slab: rendezvous = per-CTA drain (`release_cta_payload_system`) + grid barrier + acquire, then bid0/tid0 publishes ONE `(rank,slab)` epoch word to all 8 peers, parked at `row_ready[cur*T_loc_max + T_ext + slab]` (KRN:1671-1703). Service pool: slab 0 idle (or M20 prefetch, KRN:1531-1541); slab 1 quota-bounded front-half combine sweep on the `m8_front` ticket (KRN:1542-1604, quota = `effective_flush_rows`).
- **M8 combine (KRN:1846-1930).** All CTAs. tid0 polls 16 slab words (2 slabs x 8 ranks, pperr 33554432); dynamic warp tickets `m8_front`/`m8_back` (mps_state words 2/3), NT=4 tokens/batch, front chunks [0,7) then back [7,14) via `k0p6_m15_m8_batch` (KRN:629-723): local slot reads by `pull_ptr`/`pull_src` fanout, fp32 sum, **consume-and-zero** (KRN:697-706), bf16 RNE pack to `out` (32).
- **M9 retire (KRN:1932-1971).** All CTAs counted arrival on `combine_done` (33); last tid0 resets `pushed_count`/`qpush_done`/`combine_done`, bumps the epoch cell (34), **system**-scope release (the exp_29 scope fix, KRN:1952-1957), publishes `retired[cur]=epoch` to all 8 peers.

## 2. M1 transport detail

Staged row (`s_row[4][7488]`, KRN:739): bytes [0,7168) = 7,168 fp8 e4m3 payload (7 chunks x 1,024 B; quantized in-warp from bf16 with per-K128-group dynamic amax — 8-lane shfl_xor reduce, scale = max(amax,1e-6)/448, KRN:1026-1057); [7168,7392) = 56 fp32 scales (`K0P5_SC_BYTES`=224, one per 128-elem group); [7392,7456) = 64 B metadata: 8 eids (2x uint4) + 8 topk weights (2x float4) (KRN:1061-1074). 7,456 staged bytes -> 63 LL128 lines x 128 B = **8,064-byte wire row** (`K0P5_ROW_STRIDE`; header is out-of-repo, arithmetic confirmed: ceil(7456/120)=63). Destination reservation: `match_any` dedup on dest (KRN:997-1000 — one row per (token,dest), up to 8 experts fold into it), primary lanes `reserve_row` on the dest's parity-indexed `dest_counter` (agent for self, system via `peer_ptr` for peers, KRN:1003-1013; overflow pperr 65536); global receive-row id `r = cur*MAXTOK + pos` (24-bit-packed later). Acceptance bookkeeping: `pushed_count[pe]` (source side), `rows_done[src]` epoch|count, per-chunk `chunk_ready[src][c]` epoch|fill; M2 trusts the dense prefix `[0, ns)` per source segment — never per-row flags.
**bf16 dY variant:** payload becomes 14,336 B + 64 meta = 14,400 -> 120 LL128 lines = **15,360 B stride** (+90%; `a_ll` ~315 MiB -> 630 MiB), and unpack/`sc_stage`/M6's ascale path all change. The cheaper port: reuse the fp8 quant path **verbatim** — M1 already converts bf16->fp8+scales in-flight, so dY dispatch is byte-identical mechanics (precision decision, not code). Keep the weight metadata on the wire either way — it is how `swt` reaches the owner (see section 4).

## 3. GEMM phases

**Phase 1 (M6):** task = (tile, chunk g in [0,8)); tile = up to G=3 same-expert 32-blocks (`kGM=3` pinned, KRN:285-290), effective M = 96. Computes a [96 x 256] slice of **both** gate and up (paired `gu` dim), K = 7,168 = 56 K128 groups, unroll-2 K-loop with 17 loads in flight (P1:542-584); XOR-swizzled double-buffered A tile in LDS; weights loaded once per K-step, reused across sub-blocks. Epilogue: register SiLU (`gv/(1+e^-gv))*uf`, P1:611-621), per-(row,K128-half) amax, fp8 quant -> `A2q` [rowcap, 2048] + `DQ2` [rowcap, 16] (P1:675-709). **Phase 2 (M7):** task = (tile, nc in [0,16)); [96 x 448] output tile, K = 2,048 = 16 groups; 7 N16 tiles/wave, W2 streamed AGPR-staged, no LDS (P2:598-607).
**Weight addressing:** exclusively `aiter::fp8_weight_byte_offset(ew, n, k, N, K)` (P1:488-491, P2:600-604) — parametric in (N,K) — plus scale linearization `S[(e*NGROUPS + n/128)*KGROUPS + k/128]` (P1:369, P2:524-528): W13 [32,4096,7168]/S13 [32,32,56]; W2 [32,7168,2048]/S2 [32,56,16]. M20 swaps only the base pointers for pooled slots (P1 via KRN glue P1:338-352, P2:488-500).
**Transposed-weight confirmation:** with host-pre-transposed W2T [E,2048,7168] (dH2 GEMM: N=2048, K=7168 — exactly phase-1's chunk geometry, 8 chunks x 256) and W13T [E,7168,4096] (dX GEMM: N=7168, K=4096 — exactly phase-2's 16x448 nc geometry, K-groups 16->32), the bodies reuse **nearly verbatim**: MFMA core, LDS idiom, pipeline, tile/task machinery, and `fp8_weight_byte_offset` calls need only swapped dimension constants. Because the blockscale grid is symmetric 128x128, transposing fp8 values + transposing the per-expert scale grid ([E,N/128,K/128]) is mathematically exact. Caveats: (a) host must run the AITER preshuffle at shapes (32,2048,7168) and (32,7168,4096) and `is_supported_blockscale_shape` must accept them (host gate, P1:767, P2:765); (b) P1's gate/up pairing (`kW13N=4096`, `n_up = kInter + n_gate` P1:448-449, `b1s_lds[2][2][56]`) is W13-specific — for dH2 drop/repurpose the `gu` dim; the paired-register epilogue is precisely where swiglu-prime wants to emit **two** outputs (dgate,dup) from **one** GEMM + loaded saved z, into a dZq [rowcap, 4096] laid out gate-half-then-up-half (mirroring W13 columns, which is exactly the K order the dX GEMM consumes); (c) backward-P2 needs `kKGroups2` 16->32, DQ width 16->32, `dq2_lds` doubled, and the srsrc `num_records` recomputed (P2:440-442); (d) `sched_group_barrier` literals (P1:561-582, P2:655-670) are tuning hints, not correctness; (e) constants live in out-of-repo `n2_fused_moe.hpp` — give the backward TU its own constants header. Unroll-evenness asserts hold (32 and 56 even).

## 4. M7 epilogue + M8 combine; where w lives

Epilogue transport (P2:180-265): wave-local XOR transpose through `xp_lds`, then per lane 16 packed-bf16x2 remote RMWs (`accumulate_peer_bf162`, 282 static sites), address `peer_tab[xr>>sh] + ((xr&mask)*7168 + col)*2` with `slot_off` (= slots offset + `cur*MAXTOK*H*2`) pre-folded into the table (P2:356-378) — so producer `cur`'s RMWs land in owner `src`'s `slots[cur][pos]`. Depth-4 `s_waitcnt vmcnt(4)` after each RMW (throttle plan P2:154-178); deferred drain: done-hook buffers, next task head pays `vmcnt(0)+__syncthreads` (KRN:354-375, 405-408). Slab rendezvous (KRN:1671-1703) makes the RMWs fabric-visible before the slab word. **The topk weight is applied today in this epilogue**: `cf[t] * sw` (P2:194-207), `sw` from `sorted_w`=`swt` <- scatter <- `recv_wgt` <- wire metadata. M8 (KRN:629-723) is a plain unweighted fp32 sum over the token's fanout slots (local reads via `pull_src`), consume-and-zero, split at chunk 7 (7x1024 B = columns [0,3584) — the slab boundary, KRN:283).
**Folding w at combine — the trap:** M1's `match_any` dedup makes each slot row a **(token,dest)** aggregate of up to 8 experts with *different* weights; a single per-fanout-entry w at combine cannot reconstruct `sum_e w_e dX_e`. Options: (i) **recommended** — fold w in the backward dX epilogue via `swt` exactly as forward does (dispatch stays unweighted; the desired semantics "weights folded downstream of dispatch" holds; M8 reused byte-for-byte); (ii) true fold-at-combine requires per-(token,expert) slot rows — disable the dedup (fanout always 8, `MAXTOK` reservation pressure x8, slots resized) plus a `pull_wgt` array parallel to `pull_src` and a multiply inserted at KRN:697. Do not choose (ii) casually.

## 5. Service pool scheduling and wgrad filler

Pool = `bid >= nct - C` (ADP:682). It participates fully in M0-M6 and M8-M9. Idle windows: **entire slab 0 of M7** (KRN:1518 guard; ~half of M7, order 1 ms at C=16), and **slab 1 beyond the flush_rows quota** (KRN:1584-1599). M20 is the carve precedent: the last `K0P6_M20_PF_CTAS=8` pool CTAs run a host-precomputed duty table across **both** slab windows (KRN:1531-1541, engine 569-609), with "completion by kernel exit + stream order" as the whole certification — no flags. Wgrad filler CTAs should be carved identically (e.g. `bid in [nct-C, nct-kPF)`), looping expert-block dW tiles with rank-local fp32/bf16 accumulation and zero protocol: dW2 += w * dY x act(z) needs only received dY rows + saved A2q/DQ2 — schedulable from the slab-0 window onward; dW1 += w * dZ x x_rows needs dZq (backward phase-1 output) — schedulable in slab-1/post-R1/M8 windows; per-row `dw = dot(dH2, act_z)` is cheapest inside the backward phase-1 epilogue itself (dH2 already in registers, act_z = dequant(A2q)).

## 6. Forward save hooks

- **x_rows (fp8) + scales:** already persisted at the expert-owner as `a_dst` (slot 8) + `sc_stage` (slot 9) after M2 (KRN:1270-1271) and stay live all epoch. Cheapest persistence: per-layer descriptor instances pointing slots 8/9 at per-layer arenas (the M20 slots-66..70 per-layer-descriptor precedent) — zero device-code change.
- **Sort plan:** save `sti`/`swt`/`sei`/`nvi`/`tile_desc`/`pull_ptr`/`pull_src`/`pull_stage`/`chunk_ready` fills (~5 MB/layer). Critical: `reserve_row` and scatter cursors are atomics — re-derivation is **nondeterministic**, so backward must reuse the saved plan (dispatch dY into the saved rows via `pull_stage`, skip M0.5/M3-M5 entirely) to keep row/sorted spaces aligned with the saves.
- **z:** exists **only in registers** `acc[sb][gu][m][c]` (gf/uf) in P1's epilogue (P1:608-621) — never stored today. act(z) exists quantized as A2q+DQ2 (P1:675-709). Cheapest: keep A2q/DQ2 per layer (feeds dW2, dw_k) and add a mirrored quant-store of (g,u) -> new slots `Zq` [rowcap,4096] fp8 + `DQZ` [rowcap,32] reusing the existing amax machinery — keyed by sorted row, valid because the sort plan is saved.

## 7. Porting risk list

1. **Epoch lattice sharing:** epoch = slot-34 cell + 1 (KRN:305-311), advanced once per launch by M9; `dest_counter` is parity-indexed with M0 pre-zeroing the *next* parity (KRN:880-894); `rows_done`/`chunk_ready`/slab words all compare `epoch32` exactly. A backward launch on the same descriptor advances the same lattice — give backward its **own** protocol-buffer instances (epoch cell, retired, dest_counter, rows_done, chunk_ready, row_ready tail, slots) or a provably strict alternation.
2. **Retire ordering:** consume-and-zero (KRN:697-706) is sound only because M9's retirement edge orders zeroing before any peer's next-epoch RMW; keep that edge and M9's system-scope release (KRN:1952-1957).
3. **Packings:** receive row 24-bit (`0x00FFFFFF`) + `s<<24` in `sti` and `pull_stage`; `T_loc_max <= 0xFFFFFF` and MAXTOK power-of-two guards (KRN:764-781) feed the epilogue shift/mask (P2:389-390).
4. **a2_done gate is exactly 8:** `poll_local_count<8>` (KRN:326) matches phase-1's 8 chunk-tasks per 32-block; dH2's N=2048 preserves 8 — any chunking change must move both sides, and pad sub-blocks must never fire arrivals (P1:718-729).
5. **pperr bits are terminal and kernel-scoped:** bit 25 is reused as slab-word timeout here (KRN:38-40); others: 16=65536 dest overflow, 17 shape, 18 dest_counter dirty, 19 T_ext bounds, 20 scatter overflow, 21 barrier, 22 sort/tile overflow, 23 chunk_ready, 24 poll/a2, 28 config. Never clear-and-retry.
6. **`row_remaining` is a landmine:** written (KRN:1303) but stale-holed; liveness must come from settled `chunk_ready` fills only (M15_DESIGN.md gate 4; KRN:1608-1611).
7. **Slab soundness is column arithmetic:** front/back split at chunk 7 = column 3,584 must keep matching nc>=8 <=> cols>=3584 (holds while H=7168 and nc-major decode is untouched, KRN:281-283, 413-416).
8. **Dedup vs per-expert weights** (section 4) — the top silent-correctness risk for fold-at-combine.
9. **Codegen fragility near the epilogue:** register pressure at 256 VGPR/AGPR — the `slot_off` fold, `readfirstlane`, and single-textual-rendezvous rules (P2:346-408, KRN:1500-1503) exist because violations cost measured hundreds of us; the backward TU must re-run the resource/issue-run gates (M15_DESIGN.md gate 2).
10. **Ordered-before publications:** anything backward publishes for peers must precede `release_signal_batch_system` + the epoch word, like M19's decision words (KRN:1107-1128). Bump `K0P6_M15_SRC_REV`-style guards on any `.cuh`-adjacent edit (KRN:61-63).
